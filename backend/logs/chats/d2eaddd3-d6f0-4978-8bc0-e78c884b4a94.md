**Response:** 1. A **hash map** stores **key-value pairs** so you can quickly look up a value using its key.
   - Example: `"apple" -> 5`, `"banana" -> 2`

2. It uses a **hash function** to convert the key into a number, usually called a **hash code**.
   - That hash code is then turned into an **index** in an internal array.

3. The array slot tells the hash map where to store or find the value.
   - So instead of searching through everything, it jumps directly to the right spot.

4. Sometimes **different keys produce the same index**. This is called a **collision**.
   - Hash maps handle collisions in a few ways:
     - **Chaining**: store multiple entries in the same bucket, often in a list.
     - **Open addressing**: if one spot is full, look for another available spot.

5. When you **insert**, the hash map:
   - hashes the key
   - finds the bucket/index
   - stores the key-value pair there

6. When you **retrieve**, it:
   - hashes the key again
   - goes to the same bucket/index
   - checks the stored key(s) to find the exact match

7. Hash maps are usually **fast**.
   - Average time for insert, search, and delete is often **O(1)**.
   - In worst cases with many collisions, it can degrade to **O(n)**.

8. A hash map must also **resize** sometimes.
   - As more items are added, the structure expands and rehashes entries to keep lookups efficient.

9. The main idea:
   - **Hash the key**
   - **Use that to find storage**
   - **Handle collisions**
   - **Get fast lookups**
